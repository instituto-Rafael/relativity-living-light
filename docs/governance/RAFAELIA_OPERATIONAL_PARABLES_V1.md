# RAFAELIA — Parábolas-Mestres Operacionais V1

Status: `PARABOLA`. Estas referências ensinam roteamento; não substituem teste, evidência, CI, contrato de uso ou prova matemática.

## P-01 — Mestre do TOKEN_VAZIO

Quando o conteúdo de uma caixa é desconhecido, escrever `0` inventa um valor. O registro correto é:

```text
TOKEN_VAZIO
cause = por que ainda não sabemos
evidence_needed = o que precisa ser observado
falsifier = o que quebraria a hipótese
F_next = próximo gate executável
```

Referência: `governance/ethics_license_complexity_sustainment.v1.json → open_tokens`.

## P-02 — Mestre da Ponte

```text
ESTATÍSTICA → TOKENS → METÁFORAS → VECTORES → PALAVRA → PROMESSA → Ωⁿ
```

- ESTATÍSTICA mede observação, erro e incerteza.
- TOKENS nomeiam lacunas sem forçar valores.
- METÁFORAS criam pontes conceituais, sem virar evidência.
- VECTORES tipam direção, relação, risco e próxima ação.
- PALAVRA transforma intenção em especificação.
- PROMESSA transforma especificação em contrato/invariante com falsificador.
- Ωⁿ itera estados auditados sem apagar o passado.

Regra: metáfora não salta diretamente para claim.

## P-03 — Mestre do Limite Vivo

A frase:

```text
NENHUM LIMITE É REAL, POIS O CÓDIGO EXECUTA EM VERBO VIVO → Ωⁿ
```

é registrada como `PARABOLA_MOTIVACIONAL`: significa continuar procurando decomposições, rotas e testes. Operacionalmente, memória, CPU, tempo, precisão, permissões, direitos, privacidade, evidência e escopo continuam sendo limites reais e mensuráveis.

Referência: `parable_router.runtime_boundary`.

## P-04 — Mestre da Licença e da Porta

A intenção autoral é preservada, mas o roteador mantém:

```text
AUTHORIAL_INTENT ≠ LEGAL_EFFECT
LicenseRef ≠ standard SPDX equivalence
repository declaration ≠ third-party rights record
```

Se o direito de redistribuição de um artefato externo estiver ausente, a rota é `BLOCK_UNTIL_RIGHTS_RECORD`.

Referência: `license_interoperability`.

## P-05 — Mestre Ethica[8]

Ethica[8] pode orientar governança como espaço de design. Para virar grandeza física ainda precisa de definição mensurável, unidades, observáveis, dinâmica, baseline e teste.

```text
Ethica[8] design ontology = MODEL_ANALOGICO_OPERATIONAL_DESIGN_SPACE
Ethica[8] physical field = TOKEN_VAZIO_PHYSICAL_FIELD_EVIDENCE
```

Traduções operacionais iniciais: Verdade→evidência antes de claim; Humildade→TOKEN_VAZIO; Responsabilidade→proveniência/receipt/rollback; Coerência→invariantes/anti-regressão; Consciência→claim boundary explícita.

## P-06 — Mestre do Grafo

```text
coverage ≠ truth
edge_count ≠ evidence_strength
centrality ≠ causal proof
connectivity ≠ validation
```

O grafo mede estrutura. Cada aresta deve declarar relação, proveniência e fronteira de claim.

## P-07 — Mestre da Obra 🏗️

```text
fundação = autoridade + contrato
andaime = work branch
tijolo = artefato
argamassa = relação tipada
nível = gate
inspeção = teste
foto datada = receipt
rachadura = F_gap
reparo = F_next
```

Uma rachadura recebe ID; não recebe tinta por cima. Resultado negativo ou bloqueado permanece histórico.

## Regra de uso por agentes

```text
parábola → contrato → TOKEN_VAZIO existente → gate permitido → receipt → R3
R3 = <F_ok, F_gap, F_next>
```

A parábola é mestre quando ensina a encontrar o teste; nunca quando tenta ocupar o lugar do teste.
